## 1. How the audit was done, and how to re-run it

- Clean build (`npm run build:all`), then `node scripts/seo-crawl.js`. The script reads `dist/`, looks only at text and links inside `<main>` (the header nav and the sitewide link block between `</main>` and `<footer>` are ignored), and reports word counts, unique words, contextual inbound links, label leaks, long titles and missing `dateModified`. Use `--json out.json` for the per-page data.
- Data checks were one-off Node snippets against `data/devices*.json`, `data/sdcards.json` and `data/promoted-cards.json`. The checks that matter become permanent scripts in Phase C0 (see C0-2 and C0-4).
- **Always run a clean build before crawling.** A plain `npm run build:site` leaves deleted pages in `dist/`, and those show up as false findings.

### Data caveats

- **GSC data is 9 months old.** `GSC_ANALYSIS.md` stops at January 4, 2026. Priorities below come from page structure and data, not current traffic. The fresh GSC export in `ACTION_PLAN_Q4_2026.md` Sprint 1 should be used to re-rank Phases C1 to C3 before they start.
- **Corrections made during the audit** (so nobody repeats them):
  - The homepage *does* have a meta description. It spans two lines in `src/templates/home.html`, and a single-line regex missed it.
  - `kingston-canvas-select` in `data/sdcards.json` is the **microSD** Canvas Select Plus (type `microSD`), stored as V10. Kingston's datasheet (SDCS2, MKD-01102024) says **U1/V10 at 64 to 128GB and U3/V30 at 256 to 512GB**. So V10 is right for the small sizes only. (The full-size SD model, SDS3, MKD-07022025, is U1/V10 up to 256GB and U3/V30 at 512GB to 1TB, but it isn't in the catalog.) The data model has one speed class per card, so capacity-dependent ratings can't be expressed yet (see backlog).

## 3. Principles

1. **Accuracy before growth.** A page that contradicts itself does more harm than a missing page.
2. **Cite, don't claim.** No first-party testing claims. Manufacturer manuals and spec pages are fine and cover almost every device (see `REAL_WORLD_EVIDENCE_KANBAN.md` for the stricter benchmark rules).
3. **Generated content has to be specific.** If a template sentence would be identical on 200 pages, it belongs on one sitewide page that every device page links to.
4. **Copy follows `BRANDING_UX_UI_GUIDE.md`** and passes `npm run lint:copy`. No em dashes.
5. **Never edit `data/devices*.json`.** Edit `data/categories*/` sources. See `ADD_A_DEVICE.md`.
6. **Don't collide with Sprint 1.** Sprint 1 rewrites URL handling in `generate-device-pages.js`, `generate-card-pages.js`, `generate-compare.js` and others. Phase C0 stays in data files, the redirect generator and new check scripts. Phases C1+ touch generators, so start them after Sprint 1 Task 3 merges.
